# הגדרות הארגון והניתוב

בסביבה המקומית נכנסים כ״מנהל המטה״.

## המבנה הארגוני

פתחו **הגדרות הארגון → מבנה ארגוני**. העץ מתחיל במטה ארצי; לכל מחוז או סניף יחידת אב אחת. ניתן להוסיף יחידות ולשנות את יחידת האב. המערכת חוסמת מעגלים. שינוי יחידת האב משנה את תחומי הגישה בבקשה הבאה.

המבנה הקיים בהדגמה: מטה ארצי → מחוז מרכז → סניף ירושלים; מטה ארצי → מחוז צפון → סניף חיפה. אפשר להתאים את השמות והיחידות לארגון שלכם.

## משתמשים והרשאות

בחרו **משתמשים והרשאות** ליד יחידה. לכל משתמש מגדירים שם, מזהה, יחידה, תפקיד ושתי הרשאות נפרדות:

| הרשאה | אפשרויות |
|---|---|
| קריאה | ללא גישה / היחידה בלבד / היחידה והיחידות שמתחתיה |
| כתיבה | קריאה בלבד / היחידה בלבד / היחידה והיחידות שמתחתיה |

כתיבה חייבת להיות בתוך תחום הקריאה. תפקיד, הרשאות שדה והשלב הנוכחי ממשיכים להגביל את הפעולות. הרשאת כתיבה אינה עוקפת אותם. משתמש במטה עם גישה לכל העץ רואה את הארגון כולו; סניף אינו רואה סניפים מקבילים. נותן שירות ניגש רק לפניות המשויכות לרשומת נותן השירות שלו.

שינוי הרשאות או השבתת משתמש חל גם על משתמש שכבר מחובר, בבקשה הבאה. אין אפשרות להסיר מעצמך את הרשאת ניהול הארגון. שיוך מטפל מוגבל לעץ של המשתמש ולמטפלים שיש להם הרשאת כתיבה ביחידת הפנייה.

הוספת משתמש אינה יוצרת סיסמה או חשבון במערכת ההזדהות. בסביבה הארגונית המזהה צריך להתאים ל־sub ממערכת ההזדהות. בהדגמה משתמש פעיל נוסף זמין במסך הכניסה לאחר רענון.

## כללי ניתוב לפי תהליך

פתחו **ניתוב לפי תהליך**, או **כללי ניתוב לתהליך** מתוך בונה התהליכים. בחרו תהליך, הגדירו תנאים, עדיפות ויחידת יעד. קטלוג השדות כולל רק את שדות התהליך הנבחר ואת פרטי הפנייה ונותן השירות. כל כלל חדש משויך לתהליך. הכלל הפעיל הראשון שמתאים לפי עדיפות ומזהה קובע את היעד; ללא התאמה נבחרת יחידת נותן השירות.

כללים משותפים שנוצרו בגרסה הקודמת ממשיכים לפעול ומוצגים בנפרד. עריכה ושמירה משייכות אותם לתהליך הנבחר. בדיקת ניתוב בוחנת כללים שמורים ואינה יוצרת פנייה. שינויים בכללי ניתוב חלים על פניות חדשות; יעד והחלטת ניתוב של פנייה קיימת אינם משתנים.

## מפת התהליך ותנאי payload

מפת התהליך מציגה חצים, הסתעפויות וחזרות. בחרו שלב כדי להדגיש את המעברים היוצאים ממנו. בחירת חץ או פעולה פותחת את עורך המעבר. חץ מקווקו הוא ברירת המחדל כשיש מסלולים מותנים.

בעורך הפעולה אפשר להוסיף **מסלולים לפי payload**: שדה, השוואה, ערך, יעד ועדיפות. תנאים מתחברים ב״וגם״ או ״או״. סוג השדה קובע אילו השוואות זמינות. ניתן לבדוק נתוני דוגמה לפני פרסום. השרת מחליט לפי הנתונים השמורים בעת ביצוע הפעולה; שמירת נתונים בלבד אינה מעבירה שלב. ההחלטה מתועדת בהיסטוריית הפנייה. פניות קיימות נשארות בגרסת התהליך שבה נפתחו.

## אימות

הבדיקות ב־checks/organization.py, checks/integration.py ו־checks/payload.py מיועדות לסביבת הדגמה מבודדת. אין להריץ אותן על נתוני משתמשים אמיתיים: הן מוסיפות משתמשים, תהליכים ופניות לבדיקה.

להתקנת SQL Server חדשה או לשדרוג לפי היסטוריית EF: docs/migrations.sql. סכמת המודל המלאה: docs/schema.sql. ההדגמה המקומית משתמשת ב־SQLite; אין בחיבור המקומי אימות מול SQL Server פעיל.


## עדכון מסך התהליך

ניהול חוקי הניתוב נמצא כעת בתוך בונה התהליכים, בלשונית **ניתוב ליחידות** של התהליך הנבחר. בדיקת הניתוב מוגבלת לאותו תהליך. הקישור הישן `/routing` מפנה למסך התהליכים.

**תנאים לביצוע הפעולה**: מנהל התהליך בוחר לכל מעבר בדיקה מתוך קטלוג מובנה. מימוש הבדיקות נמצא בשרת, ב־`Engine.GuardError`, הנקרא מ־`Engine.Execute` לפני שינוי מצב הפנייה. הוספת סוג בדיקה חדש לקטלוג דורשת פיתוח; סימון שדות חובה והגדרת מסמכים מתבצעים במסך טופס ומסמכים. תנאי payload קובעים את היעד לאחר שהפעולה מותרת.

מפת התהליך מציגה מסלולים נפרדים לחזרות ולדילוגים, מצבי סיום בקצה התרשים וראשי חץ ברורים בכניסה ליעד. ניתן לבחור חץ גם באמצעות מקלדת.
